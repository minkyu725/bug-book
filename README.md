# Bug Book
서버, 로그인, 빌드, 외부 라이브러리가 없는 한국어 PWA입니다.

## 로컬 실행
`npm run dev` 후 http://localhost:4173 접속. Node 22 이상에서 동작하며 추가 패키지 설치가 필요 없습니다.

## GitHub Pages 배포
1. GitHub에 공개 bug-book 저장소를 만들고 이 폴더를 main 브랜치에 업로드하세요.
2. Settings → Pages → Source를 **GitHub Actions**로 설정하세요.
3. main에 push하거나 Actions의 Deploy Bug Book to GitHub Pages를 실행하세요.
4. 배포 주소를 iPhone Safari로 열고 공유 → 홈 화면에 추가하세요.
공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
상대 경로로 구성하여 저장소 하위 경로도 지원합니다. 실제 GitHub 저장소 연결 및 배포는 아직 수행하지 않았습니다.

## 기능과 범위
에너지 + 복수 태그 빠른 기록, 사용자 태그, 상황·반응·트리거·가설, 단어 규칙 기반 관찰자 모드, 기기 음성 녹음(최대 2분), 브라우저 받아쓰기, 첫 문장 추출 요약, 검색·필터·수정·삭제 취소, 7일/30일 패턴, 음성 포함 JSON 백업·병합 복원, IndexedDB 저장, 오프라인 앱 셸, 설치 아이콘.

받아쓰기는 Web Speech API 지원과 네트워크에 따라 다르며 브라우저 제공자 서버로 전송될 수 있습니다. 시작 전에 동의를 받습니다. 미지원 시 iOS 키보드 마이크를 사용하세요. 오프라인 STT, 생성형 AI 요약, 자동 동기화는 제공하지 않습니다.
https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition
브라우저 데이터 삭제나 저장소 회수 시 기록을 잃을 수 있으므로 정기적으로 백업하세요. Safari와 홈 화면 앱의 저장 공간이 다를 수 있으므로 실제로 사용할 앱에서 기록하세요. 최초 온라인 접속 후 설정에서 오프라인 준비 완료를 확인하세요.

## 검증
`npm ci` 후 `npm run check` / `npm test`
개발용 fake-indexeddb를 통해 버전 1 데이터 이전, 저장 실패 시 롤백, 삭제 취소, 동시 백업 병합을 검증합니다. 앱 자체는 외부 라이브러리를 로드하지 않습니다.
iPhone 실기기: 홈 화면 설치 → 저장 → 앱 재실행 → 비행기 모드 저장 → 음성 권한 허용/거절 → 녹음 재생 → 백업 복원. 실제 iOS 설치·음성은 실기기 최종 확인이 필요합니다.

## 업데이트
변경 시 sw.js의 CACHE 버전과 app.js의 오프라인 준비 확인 버전을 함께 올리세요. 열린 앱을 모두 닫고 재실행하면 새 버전이 활성화됩니다. IndexedDB 기록은 앱 셸 캐시와 별도로 유지됩니다.

## 1.1 개선 사항
- 350ms 후 초안을 IndexedDB에 자동 보관합니다. 에너지, 태그, 텍스트, 완료된 녹음, 수정 대상까지 복구합니다. 보관 성공 표시를 확인하세요. 강제 종료 직전 입력이나 진행 중 녹음은 복구를 보장하지 않습니다.
- 저장 중 폼을 잠그고, 기록 저장과 초안 삭제를 하나의 트랜잭션으로 처리합니다. 실패하면 입력을 유지합니다.
- 기존 기록 수정은 원래 관찰 일시를 유지합니다. 가장 최근 삭제 1건은 앱 재실행 후에도 취소할 수 있습니다. 이후 삭제 시 취소 대상이 교체됩니다.
- 검색 결과는 20개씩 표시합니다. 보이지 않는 목록의 음성 요소를 다시 만들지 않습니다.
- 백업을 DB에서 새로 읽고, 다른 창에서 추가된 ID도 트랜잭션 안에서 확인합니다. 잘못된 파일은 전체 검증 후 거부합니다. 백업은 최대 100MB이며 초안/삭제 취소 항목은 제외합니다.
- HTML과 스크립트를 동일한 캐시 버전에서 제공합니다. 새 버전이 대기 중이면 안내하고 모든 앱 창을 닫은 뒤 적용합니다. 같은 도메인의 다른 Pages 프로젝트 캐시는 삭제하지 않습니다.
- 여러 창의 확정 기록 변경은 BroadcastChannel로 갱신합니다. 초안은 기기당 마지막 작성 초안 1개이므로 여러 창에서 동시에 초안을 작성하면 마지막 보관 내용으로 교체될 수 있습니다.

기술 참고: https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers · https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event

## 확인 결과 (2026-10-12)
데스크톱 Chrome에서 한국어 입력과 관찰자 안내, 새로고침 후 초안 복원, 저장, 수정, 리포트, 오프라인 준비 표시를 확인했습니다. 개발 서버를 완전히 중지한 뒤 앱 재실행·기록 읽기·수정 저장·다시 새로고침 후 유지까지 확인했습니다. iPhone 홈 화면 설치와 실제 마이크 권한·녹음은 실기기 확인이 남아 있습니다.

## iPhone에서 기존 기록 옮기기
새 홈 화면 앱과 Safari 또는 기존 설치의 저장 공간은 분리될 수 있습니다. 빈 앱에는 이전 안내가 표시됩니다. 기록이 보이는 기존 앱에서 초안을 먼저 기록으로 저장하고 설정 & 백업 → 백업 다운로드를 실행하세요. 파일 앱에 JSON 백업이 있는지 확인한 뒤 새 앱에서 백업 가져오기를 선택합니다. 파일명, 기록 수, 음성 포함 수, 중복 수를 확인하고 기록 가져오기를 누르면 기존 기록을 유지하면서 병합합니다. 완료 후 실험실 노트와 음성 재생을 확인하세요. 취소 또는 잘못된 파일 선택 시 기록은 변경하지 않습니다. 자동 이전이나 서버 전송은 하지 않습니다. 백업에는 초안과 삭제 취소용 기록이 포함되지 않습니다.
